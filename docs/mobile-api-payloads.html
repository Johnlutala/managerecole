API mobile — guide Flutter

Contrats JSON et exemples de payloads
Gestionecole · API REST v1 · 8 novembre 2026

Les exemples utilisent https://votre-domaine comme URL de base. Toutes les routes listées sous /api/rest/v1 demandent un JWT, sauf la connexion.

1. Connexion et format commun

Connexion

POST /api/login — sans token. Les identifiants peuvent être un matricule, un nom d’utilisateur ou une adresse e-mail.

{
  "matricule": "PROF2026000123",
  "password": "mot-de-passe"
}

Alias acceptés : username ou email à la place de matricule.

{
  "code": "0",
  "message": "Succès",
  "data": {
    "token": "eyJ...JWT",
    "expiresIn": 1800,
    "user": {
      "id": 8, "username": "john", "firstname": "John",
      "lastname": "JK", "roles": ["ROLE_PROFESSEUR", "ROLE_USER"],
      "espace": "professeur"
    }
  }
}

Pour les appels authentifiés : Authorization: Bearer <token> et Content-Type: application/json. Le token expire après 30 minutes.

Réponse normale : {"code":"0","message":"Succès","data":{...}}. Erreur : {"code":"1","message":"...","errors":[]}. Codes HTTP usuels : 400 payload incorrect, 401 token absent/expiré, 403 rôle/propriété refusé, 404 ressource absente, 409 conflit d’état, 422 données métier invalides.

Important : les données sont filtrées par le compte authentifié. Ne demandez pas au mobile de transmettre l’identifiant d’un élève, parent ou professeur pour choisir son propre profil. Les opérations admin exigent ROLE_ADMIN ou ROLE_SUPER_ADMIN.

Enregistrer ou soumettre les cotations

{
  "coursId": 15,
  "mode": "noter",
  "action": "soumettre",
  "notes": {"81": {"42": "14", "43": "17"}}
}

Chaque clé du sous-objet représente l’ID d’un élève et sa cote. mode : noter pour créer, modifier pour modifier/supprimer des brouillons. action : enregistrer garde en brouillon, soumettre transmet. Cote entière de 0 au barème, max. 50 évaluations et 1000 cotes par requête. Une cote soumise/validée est verrouillée.

Créer une fiche de préparation

{
  "coursId": 15, "dateCours": "2026-11-08", "jour": "Lundi",
  "heureDebut": "08:15", "heureFin": "09:45",
  "sujet": "Le complément circonstanciel de temps",
  "reference": "Grammaire — phrase",
  "objectifGeneral": "Identifier le complément de temps.",
  "objectifsSpecifiques": "Repérer et employer un complément de temps.",
  "matiere": "Définition, exemples, exercices.",
  "methode": "Interrogative et participative",
  "materielDidactique": "Tableau, cahier",
  "activitesInitialesEnseignant": "Rappel de la leçon précédente.",
  "activitesInitialesEleves": "Répondent aux questions.",
  "activitesPrincipalesEnseignant": "Présente la règle et les exemples.",
  "activitesPrincipalesEleves": "Analysent et proposent des exemples.",
  "activitesFinalesEnseignant": "Fait la synthèse.",
  "activitesFinalesEleves": "Résolvent un exercice.",

Réponse de création : enveloppe standard avec data.id, data.numero, data.statut (brouillon), les champs de la fiche et les objets cours / professeur. PATCH accepte les champs à modifier seulement. Pour soumettre, corps vide; réponse renvoie la fiche avec statut: "soumise" et soumiseLe.

Calcul annuel

{
  "ecoleId": 1, "anneeScolaireId": 4,
  "sectionId": 2, "classeId": 3, "optionId": 5
}

sectionId, classeId et optionId sont facultatifs (omettre ou envoyer null). L’école doit correspondre à l’année et aux filtres. Réponse : {"calcules":12,"bloques":[]} ou les raisons de blocage. Le GET bulletins requiert école et année; il ne déclenche aucun recalcul.

La liste utilisateurs renvoie data.page, data.limit, data.total et data.utilisateurs[] (id, username, email, nom, prénom, rôles, actif, profil). Les bulletins renvoient data.bulletins[] avec élève, classe, année scolaire, totaux, pourcentage, décision et détails de cotation.

Réinitialisation de mot de passe

{
  "code":"0", "message":"Succès",
  "data":{"username":"john","mailSent":true,
    "message":"Le nouveau mot de passe a été envoyé par e-mail."}
}
Si l’e-mail échoue après renouvellement, l’API renvoie HTTP 503 avec mailSent:false; le mot de passe n’est volontairement jamais inclus dans la réponse JSON.

6. Recommandations Flutter

  • Stocker le JWT dans un stockage sécurisé de l’appareil, jamais dans les préférences en clair.
  • Ajouter automatiquement Authorization: Bearer ...; à HTTP 401, effacer le token et demander une nouvelle connexion.
  • Traiter data comme nullable/liste vide si l’enveloppe répond sans éléments; mapper les dates ISO en DateTime.
  • Ne pas afficher les brouillons de notes aux élèves/parents : leurs endpoints ne retournent que des notes validées.
  • Utiliser le certificat HTTPS en production. La connexion et l’API ne doivent pas être exposées sur HTTP public.

Les payloads représentent le contrat de l’API et des données d’exemple, pas des enregistrements réels. La réinitialisation de mot de passe nécessite un serveur de messagerie configuré.
